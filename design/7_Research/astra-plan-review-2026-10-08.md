# Astra: adversarial review of the training plan, 2026-10-08

The merged work materially improves diagnosis, but **the census composite is not yet a trustworthy selection objective**. Missing observations can win; losses before a saved start disappear; resuming can erase measurements. Fix those before buying more candidate evaluations. Staged B is a sound direction, conditional on a learnable observation/action contract and closed-loop clone checks. Its runtime dimensions are plausible; its time-to-trained-policy estimates are hypotheses.

Scope: reviewed main at `359efe4bc44d9f13f29ed36d244f87f8d4c86f4f`, including the two morning diagnoses, the merged plan, v3 proposal, scoring config/reducer, batch runner, vitals producer, and selected search/trainer paths. This is evidence and recommendations, not canon or authorization to adopt weights. Search/trainer staging, loaded-start overrides, and flat maps are acknowledged as in flight, not presumed finished. No builds, simulations, windows, eidolon access, AWS account operations, commits, or git mutations. Only this report was written; existing `d2.log` was untouched. Small Python fixtures exercised the existing reducer entirely in memory with bytecode writes disabled. Public AWS documentation was consulted only for the cloud planning check.

For compact citations below, `live/` means `crates/cubarium-search/src/es/voxel/live/`; all other paths are repository-relative. Line numbers refer to the reviewed checkout.

## Findings, ranked by severity

### Blocking B1 — The reducer reintroduces the required-roster omission that ACCOUNTING repaired

**Evidence:** `scripts/studies/score.py:158–178` constructs the required roster from positive counts in the first census row, plus optional configured names. `config/training/fitness-v1.toml:20–24` supplies no required names or reference counts. `score.py:197` also takes N0 from that row. On a loaded run, `crates/cubarium/examples/voxel_census.rs:591–606` emits no census row at the load boundary unless minute0 is zero. The plan explicitly requires founding/burn-in losses to count (`design/training-plan-2026-10-08.md:65,99,135–136`). In contrast, the Rust path now retains losses across founding, burn-in, and evaluation (`live/search.rs:833–884,1034–1035,1136–1137`).

**Consequence:** a species missing when the minute-60 library was made is not required by the Python scorer; one lost during the first minute after load can disappear too. A depleted starting population lowers its own population target. This is absolute-persistence forgiveness through the denominator, despite the corrected Rust accounting.

**Fix:** declare the required roster, deliberate scenario exclusions, and fixed per-lineage reference counts in the experiment/start manifest, before founding. Carry pre-start losses into the result. Emit an exact census row at every load boundary. Validate the saved start against that declaration; do not silently redefine a display-world task from whichever organisms survived. Keep dormant viability and active establishment as separate fields.

**Reproduced:** a synthetic DONE census containing a vaulttree column that is zero throughout gives L=0 and removes vaulttree from `required_plants` with the shipped config.

### Blocking B2 — Missing metrics and unequal windows still produce valid paired wins

**Evidence:** unavailable components contribute zero (`scripts/studies/score.py:82–84`); Q is always unavailable (`212`); F/S silently average only the lineages with data (`240–250`). P is still assigned, and Q alone does not even mark it partial (`253–257`). Aggregation accepts every finite P (`264–280`), and pairing requires only finite P on each side (`294–302`). The window is clipped to available observations (`145–153`); neither pairing nor the command check verifies equal observed endpoints (`323–330`). Only census timestamps are checked for monotonicity; vitals coverage, duplication, and complete per-lineage sampling are not checked (`140–157`).

**Consequence:** losing telemetry improves fitness. A nominal two-hour run with a short CSV and DONE can be compared against a full one. A sparse vitals file can look complete if each top-level component has at least one observation. This is especially dangerous around resume and reducer errors.

**Fix:** define a versioned objective profile with an explicit active-component mask, required lineage coverage, exact start/end ticks, interval rules, and units. Q can be deliberately disabled for a named short-screen profile; missing required data must make that evaluation unrankable. Compare only identical profiles and horizons. Validate telemetry endpoints, duplicate rows, finite/nonnegative counts, and expected coverage. No renormalizing across whichever lineages happened to log.

**Reproduced:** otherwise identical in-memory fixtures scored P=13.6667 with vitals and P=0 without vitals; the latter was marked partial **and counted as a valid paired win**. Separate 60- and 120-minute fixtures were also accepted as a valid pair. These are reducer demonstrations, not ecological measurements.

### Blocking B3 — Checkpointing does not yet preserve a scoreable measurement history

**Evidence:** `crates/cubarium/examples/voxel_census.rs:695–704` uses `File::create` for all three vitals files and creates a new recorder on every invocation. Loaded bodies enter as `origin="observed"`, without prior genealogy/history (`crates/cubarium-observatory/src/vitals.rs:213–249`); the scorer counts births only for `origin="born"` (`scripts/studies/score.py:110–112`). The batch launcher refuses any nonempty output directory (`scripts/studies/batch.py:234–236`). Separately, `crates/cubarium-voxel-sim/src/staged.rs:643–648` logs a save error and returns unit; its caller can then write DONE (`626–632`).

**Consequence:** resuming a census into the same vitals directory truncates earlier observations. Redirecting it elsewhere avoids truncation but leaves no defined segment merger. Surviving newborns lose their earlier birth attribution and stuck windows restart. A disk/checkpoint failure may still look successfully completed to the scorer. World recovery and experiment recovery are different requirements.

**Fix:** complete the in-flight staging work with explicit segment identities and tick intervals, checkpoint success propagation, and a reducer that joins segments exactly once. Preserve recorder continuity where necessary, or document reconstructible fields and mark unrecoverable intervals unavailable. Retain the original required roster and evaluation horizon. A tiny interrupted/resumed fixture must produce the same event totals and objective as its uninterrupted counterpart; exercise a failed save without running a long simulation. Give early ecological rejection its own terminal result, distinct from infrastructure failure and user pause.

### Blocking B4 — “Optimize P” and “report P” are currently different tasks

**Evidence:** the proposed P is in `design/training-plan-2026-10-08.md:88–120` and the Python reducer. The Rust optimizer still sums count/movement/persistence/replenishment/balance terms (`live/search.rs:313–368`) and ranks by mean penalty plus screen and box costs (`2191–2218`). That is not the Python P or its mean+0.5 SD aggregation. F, S, landscape, and hunt terms are absent from that Rust penalty. The Python reducer consumes census batch directories (`scripts/studies/score.py:314–331`), not search evaluation records.

**Consequence:** a successful launch could spend the night optimizing an older objective while the evening report implies that the new objective drove selection. ACCOUNTING repairs are real, but do not establish objective parity.

**Fix:** tonight choose explicitly between (a) using P as an external promotion gate for a named legacy/proxy search, or (b) wiring the selected objective profile into candidate evaluation. Print objective ID, component mask, weights, exclusions, and rank formula with every generation. Use the same small synthetic measurement records to compare implementations; no tuned-default regression suite is needed. This blocks claims of training against P, not bounded diagnostic work.

### Important I1 — The hard extinction rule fails after aggregation across seeds

**Evidence:** the plan says a required loss cannot be bought back (`design/training-plan-2026-10-08.md:65`) but ranks by mean P+0.5 SD (`119–121`); `scripts/studies/score.py:264–280,310` implements that rank and paired wins without a separate extinction constraint.

With shipped weights, the non-L penalties are bounded by 45, so one loss dominates within a single fully observed world. That guarantee does **not** survive averaging: baseline P=[35,35,35,35,35,35,35,35] ranks 35; candidate P=[0,0,0,0,0,0,0,100] ranks **30.1777** and wins 7/8 pairs, despite losing a required species on one seed. This arithmetic was reproduced directly.

**Fix:** separate ecological feasibility from soft ranking. Report and compare the per-seed required-loss vector first; no arm with a new required loss can pass the stated promotion rule. Among infeasible candidates, rank loss severity and then useful soft deficits so search can still progress. Among feasible candidates, use the soft score and uncertainty. If Wrysk wants a probabilistic extinction tradeoff instead, state that choice explicitly rather than promise an absolute rule.

The 6/8 sign count is a useful consistency heuristic, not strong statistical evidence: for eight independent fair signs, at least six in one prespecified direction occurs with probability 37/256≈14.5%, before searching many candidates. Report paired magnitudes and worst losses; reserve fresh confirmation seeds for finalists.

### Important I2 — F is a different formula, and its denominator is itself searchable

**Evidence:** the plan defines mean lineage `h(p25 fullness/0.4)` (`design/training-plan-2026-10-08.md:109`). The config specifies p10/0.3 (`config/training/fitness-v1.toml:39`), and `scripts/studies/score.py:240–249` averages per-minute penalties. VITALS emits p10/p50/p90, not p25 (`crates/cubarium-observatory/src/vitals.rs:606`). Fullness is reserve divided by the current body's reserve capacity (`crates/cubarium-observatory/src/query.rs:584–601`). Reserve capacity and upkeep are search genes (`config/training/search/roster.toml:121–140`).

**Consequence:** this is not a harmless label mismatch. At p10=p25=0.35, implemented F=0 while the plan's F=0.125. Shrinking reserve capacity can improve fullness without increasing energy or endurance. Fed founders can coast on imported stores, remaining above the threshold until shortly before a crash. A lineage's worst bodies dying also improves the next survivor quantile.

**Fix:** choose and document one quantile, threshold, and temporal reducer; do not silently adopt either proposal as canon. Keep fullness as a warning signal, but show reserve and digestible potential per fixed body reference, energy trend, food inflow, and projected endurance under a declared reference cost. Freeze measurement references when searching physiological denominators. Measure F by stage where immature/rider physiology differs, and display survivor counts beside each quantile.

The displayed `net_energy_per_body_hour` is not the training reward: it includes only bodies alive at both minute boundaries, uses gross `stored_energy`, and does not add offspring transfers (`vitals.rs:4–9,480–510`; compare `live/window.rs:86–151`). It can hide deaths and penalize successful reproduction. Rename it as survivor stock change; add the conserved cohort budget as the interpretation aid. The plant vitals requested by Wrysk are produced (`vitals.rs:525–550`) but `score_world` reads only animal vitals/life files and returns end stand counts (`score.py:156–157,251`). Include plant condition trends in the health report, even before assigning them a weight.

### Important I3 — S excludes hungry nonfeeders, and V can reward attempted motion

**Evidence:** stuck eligibility requires `!a.eating` (`crates/cubarium-observatory/src/vitals.rs:486–501`). That is the eating **latch**, identified separately from stomach fill in the proposal (`design/brain-contract-v3-proposal-2026-10-08.md:48–52,90`), not evidence of an actual meal. With no eligible stuck observations, the reducer converts undefined share to zero (`scripts/studies/score.py:247–248`). Moving activity is inferred from Walking/Climbing/Fly/Glide state (`vitals.rs:341–355`); the prior training meter measured delivered BL/s (`live/window.rs:603–610`). Stuck history stores positions, while exclusions inspect only the current state (`vitals.rs:175–188,335–339,486–501`). Distance is ordinary Euclidean distance (`137–145`).

**Consequence:** a hungry body pushing against an obstacle can be excluded from S precisely because its eating latch is on. An entirely resting/asleep/unobserved lineage gets S=0. A just-woken body may be judged on five minutes spent asleep. A moving state is not proof of travel; pacing around a small loop can have high path length and low net displacement. A wrap-seam crossing distorts the Euclidean measure.

**Fix:** use actual feeding/intake events and time spent voluntarily resting, separately from appetite. Keep zero eligible exposure as NA with its denominator. Require sufficient awake, nonfeeding exposure over the trailing window. Report intended effort, delivered path length, net displacement, and food access separately, using the world's wrap geometry. An always-resting fed body may be legitimate; a hungry trapped body is not. Condition and intake must arbitrate, not a universal movement bonus. Check a hungry blocked body, a sated rest, a sleep/wake boundary, a closed loop, and a seam crossing on hand-built traces.

### Important I4 — J is a coarse birth switch, not an eligibility-window or replacement measure

**Evidence:** `scripts/studies/score.py:186–196` accepts any late birth, samples any eligibility in the **whole** window, and returns 0, 0.5, or 1 via `67–72`. Slow lineages get zero weight indefinitely from a static list (`config/training/fitness-v1.toml:22`), including on a 20-hour input. No adult exposure, seasonal opportunity, readiness progression, or recruit survival enters J. N0 uses body count alone (`score.py:197–201`), while L includes eggs. Z's activation is decided once from initially free lanternjaws (`224–227`).

**Consequence:** one doomed late hatch clears J; a healthy lineage waiting for its next breeding opportunity gets the maximum deficit; slow lineages never graduate to a renewal test. For an egg-only start, N0=0 means emergence is penalized by A/K, while Z remains disabled even after adult establishment. This can select permanently unhatched eggs or nonrenewing founders. A configured 5× hard stop can also mistake normal emergence for a boom unless its reference is phase-aware.

**Fix:** declare screen/stage/complete-cycle profiles. Measure breeding opportunity in eligible adult-time and actual season/gestation state; show readiness progress in short windows and actual surviving recruitment on renewal trials. Keep laid eggs, hatchings, live births, maturation, and independence distinct. Use fixed stage-aware count bands for egg starts. Slow clocks should change the evaluated question, not permanently exempt a lineage. Test stage opportunities from mature saves, then confirm one complete cycle without replenishing failed worlds.

### Important I5 — Finite windows can favor slow starvation, synchronized booms, and sleeping through the test

**Evidence:** F and activity use the late half; counts use late means and patches late medians (`scripts/studies/score.py:152–155,198–214,228–250`). Q is absent, while energy trend and deaths remain diagnostic. The plan always starts the inner check at minute 60/dusk, uses two ranking seeds, and only later extends finalists (`design/training-plan-2026-10-08.md:123–149`). The founders' reserve-driven birth pulse is explicitly unresolved (`207–209`).

**Consequence:** one birth plus enough initial reserve can look good without sustainable intake; an early boom can leave survivors above count floors until just after the endpoint. Rest/sleep can conserve stores, suppress S exposure, and leave only the browser's V penalty. Starting every test at dusk confounds policy quality with nocturnal advantage and a shared founding-age cohort. Neither a 1.5-hour nor a two-hour test establishes seasonal replacement.

**Fix:** retain quick paired screens, but add start-to-end stock budgets and terminal slopes/drawdown to the vector. For comparable full-day trials, implement Q with explicit zero-income, nonpositive-denominator, death/transfer, and imported-stock rules; do not divide by an unstable near-zero denominator. Pair within each phase, then sample several declared day/season/age phases across starts. Promote on held-out phase/seed combinations and run a continuation beyond the screen horizon. Do not average different lifecycle profiles into one score. Evaluate fresh establishment separately from robustness of preconditioned mature worlds.

“Failed runs count” needs an operational definition: the current reducer correctly keeps failed/paused/missing jobs and invalidates their arm, rather than dropping them (`score.py:126–135,264–280`). Keep that behavior for infrastructure failures; record a completed ecological early rejection as a failure outcome with a reason, not as missing telemetry or a shortened successful evaluation. Do not impute a stable tail after a crash.

### Important I6 — Staged B is sensible, but the proposed observation is not equivalent to the teacher's information

**Evidence:** one best Threat/Kin/Prey slot replaces directional cone classes, claimed to carry the same information (`design/brain-contract-v3-proposal-2026-10-08.md:92–104`). Places is range-limited but sourced from route queries (`99,106–109,413–422`). Cloning assumes that recording executed action carries over the reflexes to the extent observations explain them (`213–216`); success is framed partly as Steer-source agreement (`241–247,325–329`).

**Consequence:** nearest/best-target compression loses the bearings of other threats/kin; a count cannot restore them. A bearing to a destination is not the bearing to a traversable next step. An in-range query can still leak occluded/global route knowledge. A teacher using longer-range targets, private hysteresis, home memory, or a different sampling clock may emit conflicting labels for identical brain observations. A global action agreement score will be dominated by ordinary foraging and can hide complete failure on rare escapes. B does not itself output a Steer-source classification.

**Fix:** before fixing the manifests, make a table for every overridden behavior: required information, causal observation timestamp, action/hold duration, internal state, and whether it remains learnable. Decide whether Places is a sensed landmark, remembered home, or local route guidance; specify validity, stale-target handling, range, and path-versus-Euclidean distance. Where a teacher uses unavailable information, restrict the teacher for that dataset or explicitly expose the needed observation. Record at controller decision times with matching observations and a well-defined post-override action, not mismatched tick samples. Validate teacher-forced loss **and closed-loop behavior**, stratified by escape, drowning risk, roosting, feeding, and rare events. Use short resettable challenge scenes before broad predator-world ES.

B remains my recommendation for the eight nonpack lineages. Curriculum and explicit information are the important conditions. A is not mathematically incapable of later learning—the override could be faded or trained around—but permanent overriding reflexes would constrain the requested learned behavior. That is sufficient reason to prefer B without overstating the argument against A.

### Important I7 — The recommended pack exception does not fit the proposed runtime/action budget

**Evidence:** C outputs K option logits **plus** low-level actions (`design/brain-contract-v3-proposal-2026-10-08.md:253–256`); the Veilhound table lists five options (`270`) and B already has four motor outputs (`202`). P3 and imitation are scoped to O≤5 (`218–219,372`), while P8 later adds the pack option head (`377`). Option 0 is described globally as own steering, but several option tables inconsistently include or omit it (`254–270`).

**Consequence:** the recommended C pack needs nine outputs under the stated interpretation, not four or five. Runtime, imitation loss, manifests, policy serialization, action resolution, and parameter counts must agree from the start. Otherwise the claimed single schema/refusal transition becomes a second incompatible package. Per-body option choice can also dismantle coordination when pack members choose different skills.

**Fix:** reserve a typed categorical option head plus typed continuous action head in the v3 schema; define K unambiguously. Specify who decides the pack option, how teammates agree, skill initiation/termination/interruption, and what happens when an option is inapplicable. Do not charge an unconstrained pack refactor as a small add-on to an O≤5 runtime. Shared policy weights are not shared decisions.

### Important I8 — Awake-only and pack rewards need a conservation and sampling contract

**Evidence:** the plan proposes awake-only scoring (`design/training-plan-2026-10-08.md:78–86`), and v3 P5 says a sleeping window scores nothing (`design/brain-contract-v3-proposal-2026-10-08.md:374`). Pack reward sums member energy including pups and escrow (`354–359`). Current rewards preserve death loss and offspring transfer (`live/window.rs:118–151`); the trainer gives an unobserved candidate score zero (`live/trainer.rs:136–157`) and updates if there are two bodies total, not two adequately sampled signs per pair (`355–384`). New controllers are installed each window (`live/window.rs:437–440`).

**Consequence:** deleting sleeping intervals can erase overnight death, metabolic costs, and the consequences of choosing a roost. Adding member energy and the usual offspring-given term double counts within-pack transfers unless the latter is removed. New members, dispersal, death, and variant changes create credit boundaries. With few bodies, a score-zero unplaced variant is not a measured control; normalization cannot repair that missing counterfactual.

**Fix:** keep biological energy/death/transfer accounting continuous over a fixed wall-of-simulation horizon. Mask policy-action exposure or report awake-conditioned diagnostics without erasing consequences. For packs, use a declared cohort/control volume: internal pup provisioning cancels, births do not create reward twice, and external transfers/membership changes are booked explicitly. Use one perturbation per coordinated pack and require sufficient observations of both signs before an update. Run σ=0 placement controls, preserve/report reset semantics for GRU state and curiosity memory across windows, and verify a frozen-policy closed-loop evaluation separately from mixed-variant training worlds.

### Important I9 — The resource plan lacks aggregate memory, measurement overhead, and content identity

**Evidence:** `scripts/studies/batch.py:124–139` limits each child to 64 GiB, while its concurrency calculation is CPU-only (`193–200`); multiple batches do not coordinate. It records a binary digest and command paths (`246–254`), but not config/start/policy content digests or the scoring config. `score.py:323–330` compares path arguments, not their contents. The observer traverses bodies and life state each tick (`crates/cubarium-observatory/src/vitals.rs:213–267`) and records per-body histories. The plan's throughput figures predate the merged speed package (`design/training-plan-2026-10-08.md:45–53`), and its cloud sketch claims 128 parallel worlds (`170–171`).

**Consequence:** per-child limits can still exhaust the host in aggregate. A restart under a changed file at the same path can mix different inputs under one experiment name. Scoring later with edited weights silently changes rankings. Cheap cold worlds do not bound mature-world observer, save, or I/O cost; the healthy booming candidate may be the slowest and largest one.

**Fix:** before filling available slots, measure a short mature segment **with vitals and checkpointing on**, then size concurrency from CPU, measured high-water RSS, storage throughput, and shared load. Apply a batch memory envelope and bounded wall budget as well as per-process limits. Record resolved parameters, actual accepted seed, start identity/phase, drivers and policy hashes, objective config/hash, binary hash, and water cadence in a small manifest. Preserve summaries and bounded latest checkpoints, not archival build copies.

For later EC2, two c7g.16xlarge hosts provide 64 vCPUs each; the existing 90% reserve permits at most 57 one-thread workers per host before other constraints, **114 total, not 128** (`WORKING_POLICY.md:116–124`; [AWS C7g specifications](https://aws.amazon.com/ec2/instance-types/c7g/)). This is a census concurrency ceiling, not permission to exceed the separate episode-trainer cap. The $18–30 sketch is not a verified regional Spot quote. Reprice a capped single-host pilot at launch; retain the owner's go/no-go. Recovery must tolerate loss without a final save: interruption notices are best effort, so two minutes is not guaranteed ([AWS interruption documentation](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/spot-instance-termination-notices.html)).

## Gaps nobody listed

These are additional design risks or missing operational definitions, not claims that an observed run has already exploited them.

- **Changing the unit of health while optimizing it.** Reserve-capacity search changes F's denominator; body-size and speed changes alter body-length novelty and motion units; clock genes change how much biology fits in “two hours.” Keep ecological genes separate from evaluator reference units and log both. Evidence: `config/training/search/roster.toml:118–140`, `query.rs:584–601` under `crates/cubarium-observatory/src/`, and v3's action/curiosity proposal at `165–169,349–353`.
- **Mixed-policy performance is not all-policy performance.** In shared training worlds a mutant can eat forage made available by other variants, or exploit prey/packmates that will disappear when every body uses the winner. Fixed ecology does not make the visited world distribution stationary. Evaluate the frozen centre installed in the whole focal lineage against frozen opponents, then against a small opponent/start repertoire before updating the other side. Evidence: `live/window.rs:431–442`, `live/trainer.rs:355–384`; the plan separates loops but does not specify this deployment-mixture check (`143–148`).
- **A checkpoint is also a controller-history boundary.** A world with correct stock and positions but reset GRU hidden state, target memory, curiosity, or observer history may be a different experiment. Specify what a fresh branch intentionally resets versus what a continuation must preserve. Count a short matched post-load settling interval without dropping deaths from hard losses. Evidence: window controller installation at `live/window.rs:437–440`, observer recreation at `voxel_census.rs:695–704`, and v3's saved-start retirement proposal (`389–393`).
- **Largest-component share is not founder access.** A map can have a 99% connected floor while every tested founder, edible crown, shore egg site, or refuge is in the other 1%; topology changes as water/vegetation change. Add founder-to-resource reachability and time/path cost at the body's actual size and mobility state, and sample after habitat changes. The promised readout is only largest walkable component share (`design/training-plan-2026-10-08.md:165–166`).
- **Repeated peeking consumes the held-out set.** “Held-out every few generations” becomes validation, not final holdout; repeatedly selecting starts that survived also selects easier ecologies. Keep training seeds, reusable validation starts, and untouched final confirmation seeds separate, with start-construction policy and rejected-start counts recorded. Rotate ranking seeds within blocks while keeping the baseline paired. Evidence: `design/training-plan-2026-10-08.md:135,145–148` and `scripts/studies/batch.py:201–214` (one start per seed cannot represent multiple phases without extending identity).
- **The owner needs an observable choice, not thirteen penalties.** Prepare one compact page with all per-seed losses, stock trajectories, adult/young/egg counts, plant vigour, awake/intake/stuck exposure, and the two or three tradeoffs that changed the ranking. Show synchronized headless clips at fixed camera/time/scale for baseline and finalist; include a bad seed, not only the prettiest one. Do this later under the normal capture budget, not by archiving every candidate. Current plain output is numerical only (`scripts/studies/score.py:377–412`), and the plan postpones visual thresholds to captures (`197–203`).

The stock-and-role question remains mandatory. No new run here establishes which stocks currently diverge. The next readout should explicitly ask: litter accumulation→shredder access/consumption; fungal-cap accumulation→capgnawers; carrion accumulation→actual scavenger meals; prey surplus→hunters; foliage/meadow decline→browser demand, woody competition, and wet/dry habitat; nutrient immobilization→recycling pathways. Show stock change **and** the answering role's accessible intake before adjusting rates (`WORKING_POLICY.md`, “Balance through roles”). A scalar improvement alone cannot answer this.

## Five recommendations for the next six hours
