# Independent source review of the in-progress care core

Reviewed the working-tree versions of `care.rs`, `world.rs`, `water.rs`,
`snapshot.rs`, `snapshot/v7.rs`, and telemetry on 2026-09-12 while the core worker
was still completing its tests. This is a bounded source review, not a claim that
the final implementation or its tests failed. No production files were edited.

## Correct the allowance boundary for rim feeding

`World::feed` (`world.rs:1121`) tests `allowance_used + 3 > 30`, while it increments
the allowance by the floating-point sum of the actual footprint deposits. A rim
cell with three neighbours has normalized weights `0.4, 0.2, 0.2, 0.2`. Summing
`3 * weight` gives `3.0000000000000004`, independent of where the centre appears
in the sorted four-cell order. Nine such feeds leave
`allowance_used = 27.000000000000004`; the tenth is rejected as exhausted.

The nominal 30-unit allowance therefore permits ten interior feeds but only nine
rim feeds. This arithmetic was reproduced directly with IEEE-754 doubles; no
Rust integration test was run by this reviewer. Use a consistent small tolerance
or canonical allowance bookkeeping at the admission boundary, while retaining
actual material/energy source sums. `CareState::validate` already permits rounding
slack on the stored allowance. Add a ten-feed rim regression and confirm an
eleventh feed is still refused without cleanup.

## Tighten active-shower snapshot validation

`CareState::validate` (`care.rs:231–266` in the inspected version) checks delivered
samples below 120 and start tick no later than the world, but not their relation.
An active shower admitted at B must have
`delivered == world_tick - B`, with the difference below 120. At tick B+60, a
snapshot with `delivered = 0` currently validates and restarts at envelope sample
zero, redelivering earlier rain despite the already advanced water state and
ledger. Normal snapshots generated by the step loop appear to keep this relation;
this is a malformed-snapshot acceptance bug, not evidence of normal restart drift.

Also reject duplicate footprint cell IDs and a zero shower sequence. A shower
sequence must satisfy `1 <= seq <= admitted_seq`. The current checks admit both
duplicates and sequence zero. Use the documented `WEIGHT_TOLERANCE` (1e-12) for
normalization: validation currently allows 1e-9, so a crafted but accepted shower
can exceed the dose accuracy promised by the contract. Existing generated
footprints are unique and normalize more closely; these are decode hardening fixes.
Minimal invalid fixtures: `tick=60, B=0, delivered=0, seq=admitted_seq=1,
cells=[0], weights=[1]`; or at `tick=B=delivered=0`, use `cells=[0,0],
weights=[0.5,0.5]`; or use one cell and `seq=admitted_seq=0`. All currently pass
the inspected care validator. For tolerance alone use one weight `1-5e-10`.

`World::check_invariants` currently checks fields and organisms but omits
`care.validate(self.state.tick)`, although `WorldState::validate` includes it.
Include the care checks in the runtime invariant path so a runtime progress or
ledger defect is caught before writing an unloadable checkpoint. Focused malformed
snapshot tests should change one property at a time; a normal mid-shower round
trip should remain bit-identical after the remaining samples finish.

## Source paths that look consistent, pending final test evidence

The no-shower branch passes `None` into `water::step` and retains the pre-care
natural-rain arithmetic in its original order. Other ecological operations and
RNG calls were not changed by the inspected diff. Additional mass/energy audit
terms are zero with no care and do not modify ecological state. The decisive
cross-version evidence remains the genuine schema-7 fixture continuation test;
its completion belongs to the core worker and was not assumed here.

Feed imports `D` plus `De`; cleanup removes their matching fractions and books
material and chemical-energy exports without classifying export as heat. The
material residual and loaded baseline use matching care signs. Rain adds the
manual rate before flow/growth, publishes the combined rate, books the combined
water source once, and attributes its manual share separately. The sample cursor
advances once per tick and retires at 120. No additional normal-path accounting
defect was identified in this bounded source pass.

The schema-7 mirror preserves the old top-level order and conversion appends only
default care. The projection removes only care. No current migration logic fault
was identified; shared nested types remain unchanged in this patch. The mirror
reuses those nested types, so its “frozen” contract still depends on preserving
their future serialization shapes. That is a maintenance constraint, not a request
to redesign the migration in this slice.
