## 3. Traps the next worker must know

1. **The daemon decides its one-client rule at `accept`, not at `Attach`**
   (`handoff/server.rs`, `if client.is_some()`). Any *second* socket this process
   holds open — including a placeholder created to fill a struct field — **is**
   the attached client, and the real connection then refuses itself. This cost
   half an hour of blaming a neighbour in Stage A. `shim.rs` opens exactly one
   socket, in `connect_when_free`, and says so.
2. **`Present` must not be waited on.** The daemon answers once the flip has
   *completed*, so waiting there puts a refresh on the host's critical path: it
   was the difference between 34 and 59.5 fps. Replies are drained in
   `take_free_slot`, which needs one anyway because `released` is the only signal
   a buffer is free.
3. **`Attach` carries slot 0** (the daemon picks and says so in the reply) and
   **`Present` describes nothing** — width, height, fourcc, pitch and offset are
   all reserved and must be zero. Both are unit-tested in `shim.rs`.
4. **A nearest sampler turns a half-ulp of interpolation error into a whole wrong
   texel.** The tile coordinate is computed in the fragment from `gl_FragCoord`
   and flat instance data, never interpolated. Undoing that took board-vs-desktop
   agreement from 0.116 to 1.10 mean \|Δ\| in Stage A.
5. **`ArtGeometry::species_of` calls `slot_of`**, which is seven `SplitMix64`
   draws and an `embed_tangent`. Never call it per cell per frame; `sink/gpu.rs`
   lays the slots out once and reads `habitat`'s plant table directly.
6. **`ArtPresenter` snaps on its first observe rather than advancing**, and leaves
   `tall_prev == tall` when it does. The sink's column-height snapshot is taken
   *before* an ordinary advance and *after* a snap; getting that backwards makes
   every column grow from nothing over one tick (it showed as 0.50 → 3.23 in the
   fidelity test, which is how it was caught).
7. **The art does not scale with `S` on the CPU.** `art_present` passes
   `scale = 1.0` to every stamp, so a 16 px tile is 16 raster pixels at every
   `--world-scale`, contradicting `flat-world-plan` §6. `--gpu-art-scale` shows
   both; the default is the presenter's rule so that the reference stays the
   reference. **This is an open design decision, not a bug to fix.**

## 4. The interfaces, as they now stand

```rust
// crates/cubarium/src/sink/mod.rs — three defaulted, object-safe additions
fn observe_world(&mut self, view: &RenderView, hunters: &[HunterView], events: &[HunterEvent]);
fn observe_view(&mut self, view: &RenderView, seconds: f64, f: f64) -> Result<()>;
fn wants_pixels(&self) -> bool;          // false lets the host skip the canvas entirely
```

The runner calls `observe_world` where it calls `presenter.observe_hunters`, and
`observe_view` where it calls `presenter.draw`; `wants_pixels` gates the draw,
the care overlay, the encode and the submit. `FanOutSink` forwards all three and
wants pixels if any child does.

```rust
// crates/cubarium-gpu/src/adapter.rs — one stamp to one instance
pub struct Stamp { anchor, heading, layers: [PoseRef; MAX_POSES], bend: [f32;4],
                   mask: StampMask, tone: Option<StampTone>, opacity, scale,
                   scratch: Option<ScratchFrame> }
pub fn Stamp::instance(&self, atlas: &Atlas) -> (SpriteInstance, usize /* frames dropped */)
```

`SpriteInstance` is 120 bytes, ten vertex attributes, four `(frame, weight)`
slots. The CPU-pass → layer/instance mapping table is §1 of the main report and
is repeated in the `adapter` module doc.

New flags, all on `cubarium run`:
`--sink gpu`, `--gpu-target shim|window|headless`, `--gpu-filter nearest|bilinear`,
`--gpu-art-scale <f>`, `--gpu-bend-substep`, `--gpu-capture <dir>`.

   It is the one open decision that changes the look, it is one flag, and
