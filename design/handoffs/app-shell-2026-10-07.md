# App shell: pause menu, save slots, new-world setup; Rust or Godot

Wrysk, 2026-10-07: "thinking ahead to making it more into a game / usable app: id want a
pause menu so esc doesnt just exit the program. and like save slots that can be set/accessed
within the game. and a new-world setup where you like pick the size, preset terrain types,
and it generates like 3-4 seed worlds for you to pick one. we could either do this in rust
or go with the godot harness we have previously talked about. and later on, all the
api/metric stuff i asked for above will just be reused internally as ABI to the godot
harness/UI." Also the in-world half of: "ideally, i would be able to hover/click on an
animal and see its stats and life history."

Standing order: the ambient piece comes first and the game later, on the same engine. This
is the bridge between them.

## What exists

- **Engine evaluation**: `design/handoffs/fable-voxel-world-first-wave-2026-09-16.md`,
  section "Engine choice" (Godot with a Rust core to evaluate, Bevy as the alternative), and
  `design/game-roadmap-2026-09-16.md`. Godot was later dropped as the preview; the render bed
  is `cubarium-gpu`, and Godot 4.7 remains the art baker.
- **Renderer**: custom wgpu (`crates/cubarium-gpu`) with its own wayland-client toplevel and a
  presenter thread (merged 05e6d979), plus headless capture.
- **Saves**: whole-world save on demand (`save [DIR]`, Ctrl+S, SIGUSR1; `--load DIR`), merged
  6cb8abe7, as the layered world/flora/fauna snapshot. A schema change refuses old worlds
  (always fresh, never migrate), which matters for slots kept across versions.
- **Observatory** (in flight, `design/handoffs/observatory-api-dashboard-2026-10-07.md`): a
  transport-free query layer plus HTTP. It is meant to become the UI's data interface,
  including `/animals/{id}` with life history.
- **World sizes**: the terrarium presets, and 1.5× and 2× depth variants in flight
  (`design/handoffs/deep-world-2026-10-07.md`).
- Esc quits today.

## First decision: Rust UI or a Godot shell

The orchestrator's lean (Opus, 2026-10-07): stay in Rust for this step. Draw an
immediate-mode UI (egui through egui-wgpu) over the existing presenter for the pause menu,
the save slots, and a new-world wizard whose 3–4 seed thumbnails come from the existing
headless renderer.
- The renderer is custom wgpu. A Godot shell means either sharing a GPU texture across APIs
  or porting the renderer into Godot.
- The menus are small, and the panel build stays one binary.
- Keeping the observatory's query layer transport-free leaves a Godot GDExtension shell
  open for later, if the game needs an editor, input remapping, controller support or
  platform export (Godot's real strengths).

Wrysk's call.

## Then

1. Pause menu: Esc toggles it and pauses the sim. Resume, Save, Load, New world, Quit.
2. Save slots: named slots in a per-user saves directory, each with a thumbnail, the world
   day and a species summary from the observatory. Loading a wrong-schema save gives a plain
   message.
3. New world: size (panel, terrarium, deep 1.5×, 2×), terrain preset and climate preset.
   Generate 3–4 seeds in parallel, headless; show their thumbnails; pick one.
4. Inspect in the world: hovering highlights an animal and clicking opens its stats and life
   history (the observatory's animal data). Needs screen-to-world picking in the presenter.
