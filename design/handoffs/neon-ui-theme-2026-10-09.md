# Neon UI theme as editable Godot resources (2026-10-09)

**Rules.** `design/handoffs/worker-rules-2026-10-07.md` applies in full, along with AGENTS.md and WORKING_POLICY.md. The hard ones:
- **No windows.** Every Godot run goes through `scripts/hidden.sh`.
- **The 5-minute rule.** Wrap anything long in `timeout 270`; never wait on jobs.
- **Commits.** Explicit paths only, never `commit -a`. The commit trailer is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No extension rebuild.** Never rebuild `game/bin`. Copy main's `game/bin/libcubarium_godot.so` into your worktree for headless runs.

## Objective

Wrysk picked the game UI's look over three mockup rounds, and wants to **edit it by hand in the Godot editor** ("yes, editor-first").

Build the look as Godot resources, not code:
- a theme;
- font resources;
- small `@tool` style pieces for the pixel effects;
- two scenes laid out in the `.tscn` itself.

Opening them in the editor must show the real look, and every number and colour must be an Inspector field.

The spec is `design/ui/design-language.md`. Its values are binding. The reference rendering is `design/ui/round3/index.html`. Its defaults are his picks; open `#shot&view=screen` and the sheet's "Lit dots" and "Glow" sections in headless Chrome.

The type test `design/ui/round2/godot/specimen.gd` shows what already works in Godot 4.7:
- `FontVariation.variation_opentype` keyed by `TextServer.name_to_tag`;
- fractional axis values;
- Gridlite with antialiasing gray, hinting none, subpixel positioning off;
- notched rings drawn as four rectangles;
- the scrim shader.

That specimen builds everything in code. Don't copy that structure.

## Deliverables (all under `game/` unless noted)

### 1. Fonts

Fonts live in `game/fonts/`. **Font files never go into git** (Wrysk: "dont commit any fonts").
- Gitignore `*.ttf`, `*.otf` and `*.woff*` there.
- **Do commit the `.import` files**, so the import settings travel. They are:
  - Gridlite: antialiasing gray, hinting none, subpixel off, no mipmaps, no MSDF.
  - Pixelify: antialiasing gray, hinting light.

Add `scripts/fetch-ui-fonts.sh`:
- It downloads Pixelify Sans (OFL), `PixelifySans[wght].ttf`, from `https://raw.githubusercontent.com/google/fonts/main/ofl/pixelifysans/`.
- It copies Gridlite from `~/Downloads/GridlitePEVFTRIAL-All.ttf` if that file exists. That file is a trial licensed for testing only.
- It prints what's missing.

Add a short committed `game/fonts/README.md` covering:
- where each font comes from;
- that Gridlite needs a Rosetta Type licence before shipping;
- that the trial replaces 2, Q, X, q and x with a placeholder box.

For your own runs, copy:
- `~/Downloads/GridlitePEVFTRIAL-All.ttf`;
- `design/ui/round2/fonts/pixelify-sans/PixelifySans[wght].ttf` from main's worktree. It's untracked, so read it from `/home/wrysk/wryskware/cubarium`.

Then run `godot --headless --path game --import`.

### 2. Font resources: `game/ui/neon/fonts/*.tres`

Each is a `FontVariation` over those files, with the axes from the spec:
- title;
- chrome, with 2 px glyph spacing;
- chrome for keycaps, with no spacing;
- chrome negative, the lit plate: `'wght' 1, 'BACK' 700, 'RECT' 700, 'ELSH' 2.65`;
- chrome pressed: `'wght' 900, 'BACK' 240, 'RECT' 240, 'ELSH' 2.65`;
- chrome secondary: `'BACK' 320, 'RECT' 220`, the rest as chrome;
- text, Pixelify weight 400.

Gridlite sizes stay multiples of 13 px: 26 for chrome, 52 for big numbers, 91 for the title. Text sizes are 23, 21 and 18.

### 3. Style pieces: `game/ui/neon/*.gd`, each `@tool` with a `class_name`

Every property is `@export`ed so the Inspector edits it.
- **Notched frame.** Optional fill, a 3 px ring with cut corners drawn outside the rect, and an optional soft glow. Used for the main panel, inner boxes, the tab bar and the secondary button.
- **Dithered bands fill.** The five band colours and edges, a 3 px cell, a 4×4 Bayer ramp over ±15 px at each edge. Cache a generated texture per size.
- **Dot plate.** For the selected list row and chips: 2 px dots on a 4 px grid, a colour, and an optional left bar.
- **Glow focus.** A 3 px notched cyan line 6 px outside the rect, plus an 18 px glow.
- **Scrim.** A `canvas_item` shader with its material resource.

Prefer custom `StyleBox` subclasses (the `_draw` virtual), so they slot into the theme's style slots. Verify that they draw in the editor and at run time, and that drawing outside the rect isn't clipped.

If something can't be a `StyleBox`, use the nearest editable thing and say why. That might be a `@tool` `Control`, or a `StyleBoxTexture` generated by a committed script with exported parameters.

### 4. Theme: `game/ui/neon/neon_theme.tres`

- The default font is text, at 23.
- Type variations cover every component in the spec's "Controls: lit dots" and "Focus: glow" sections:
  - title, big number, kicker, fact label, chrome label, body, list and small text;
  - main panel and inner box;
  - tab and selected tab;
  - main button and secondary button;
  - list row, chip and selected chip;
  - keycap.
- Disabled is 40 % (font and style alpha).
- Focus everywhere is the glow focus.

Godot's Button and Tab theme have one font for every state. Where the lit style needs the font to change, add a small script, for example a tab strip that swaps `theme_type_variation` on selection. The cases are:
- the selected tab is negative;
- a pressed main button switches to the pressed setting.

**Hover isn't designed.** Make hover match focus, and list it as an open question.

**Upper case** is a Label property, not a theme one. Set it in the scenes for chrome labels.

### 5. Scenes, laid out in the editor format: nodes and properties in the `.tscn`, scripts only for behaviour

- **`game/ui/neon/gallery.tscn`.** Every component in every state on the main panel over the world backdrop (`design/ui/round1/assets/world.png`; copy it into `game/ui/neon/` if needed) and the scrim. Include tabs, both buttons (normal, focus, pressed, disabled), rows (normal, selected, focus), chips, keycaps and each label style.
- **`game/ui/neon/field_guide_mock.tscn`.** The Lanternjaw field-guide page from round 3, using containers and the theme. Use static sample content from the round 3 page, and the plate art `design/ui/round1/assets/lanternjaw-px.png` drawn with nearest filtering at 528 px wide. The next package wires it to live data, so keep a clean node structure with readable names:
  - species list;
  - plate;
  - live count with a bar chart (a small `@tool` control with exported values is fine);
  - entry text that scrolls above fixed buttons;
  - facts grid;
  - chips;
  - key hints.

Lay out a 1920×1080 composition centred in the window. The project has no stretch mode. Leave `main.gd`, `game/ui/theme.tres` and the existing menus alone; switching them over is a later step.

## Verification

2. Run each scene through `scripts/hidden.sh` at 1920×1080 and 2560×1440, saving one frame: a tiny `--shot` hook, or a `-s` script. On the gallery, give focus to one button and one row.
3. Screenshot round 3 in headless Chrome with the same view. Build side-by-side images and list every visible difference. Fix the ones that are bugs; report the rest.
4. Check that the Gridlite sizes are multiples of 13 and the text sizes are 23, 21 and 18.

Cosmetic UI needs no separate test pass. The screenshots are the verification.

## Authority and exclusions

- **Values.** Where the spec or the round 3 CSS gives a value, use it. Where both are silent (hover, paddings the CSS doesn't pin, row heights in Godot units), make the smallest call that matches round 3, and list each one in your report. Don't invent new looks.
- **Out of scope:**
  - live data;
  - dossier text;
  - porting existing menus;
  - the populations/metrics screen;
  - settings controls (sliders, toggles);
  - sound;
  - any Rust;
  - merging. The parent merges.
