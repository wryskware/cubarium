## Why

BRAIN-FIX (merged f1590fb5) built the lanternjaw's stage-1 training. Read:
- `design/handoffs/brain-fix-2026-10-12.md`;
- `design/lanternjaw-stage1-training-2026-10-12.md`;
- the merge commit's message.

Two things went wrong after it handed back.

1. **The smoke run panicked.** Job `1012-124416-brain-fix-lj-stage1-smok-200d` died with
   `runs/lab/<job>/run/stderr.log`: "terrain seed 5386312464871757709 rejected: no 0.5 m closed
   walking route", at `live/world.rs:89` from `live/trainer.rs` `found()` (~line 446).
   - The founding tried 7 terrains and kept a refused one, and `found_world` panics on it.
   - The clone tool already skips refused seeds (BRAIN-NEXT). The live trainer doesn't.
2. **The lanternjaw clone recorded no hunting.** Rerun `1012-122230-brain-fix-clone-lanternj-e4ac`
   (`run/stdout.log`) gave these labels:
   - rest 16,320;
   - feed 1,575;
   - give way 345;
   - patrol 0, ambush 0.

   The new mapping (`intent.rs` `teacher_label`, Lanternjaw: `S::Patrol if !a.eating => rest`)
   turned the old 16,705 patrol samples into rest. Its competence:

   | mode | rules | two-layer | plain |
   |---|---|---|---|
   | feed | 1.00 | 1.00 | 1.00 |
   | give way | 0.63 | 0.26 | 0.05 |

   The first clone also found all three arms' live energy equal to 1e-9. Together these say the
   lanternjaws in the teacher worlds are sated and digesting nearly all the time. If so, a clone
   or a stage-1 run there has nothing to learn about hunting.

## Do

Commit after each numbered step.

1. **Refused terrain.**
   - When the founding refuses a window's terrain, the live trainer draws another seed in a
     deterministic way, with a note in the run log. Pick a sensible attempt cap; past it, the
     error is a clean `Err`.
   - Worlds whose first seed is accepted must found exactly as today. The ecology thread's plain
     training must stay byte-identical (`a_plain_lineage_trains_exactly_as_today`).
   - Check the brain check's fixed seeds (`--check-seeds`; 21 is a known refused seed) the same
     way.
2. **The lanternjaw's rest label.**
   - Read the eating latch's meaning in `hunt.rs` / `hunt::steer` and check the mapping against
     what the body actually does: trace a sated and a hungry lanternjaw in a training world.
   - If the label is wrong, fix it, and fix its test (`the_lanternjaws_patrol_states_map_to_its_menu`).
   - If it's right, say so with the trace.
3. **Teacher streams that hunt.**
   - Record lanternjaw teacher streams where lanternjaws are hungry. Use the existing
     `--top-up` (fullness) or staged scenes, so patrol and ambush appear in the hundreds or more.
   - Rerun the lanternjaw clone (spec: `scratchpad/bf/clone-lanternjaw.toml`) and report the
     per-mode table beside e4ac's.
4. **Training.**
   - Resubmit the smoke run (`scratchpad/bf/lj-smoke.toml`, from the new clone's centre).
   - Once it's written back, submit the real run (`scratchpad/bf/lj-stage1.toml`, updated to your
     binaries and the new centre) so it queues.
   - The real run must start only after its inputs exist. Hand back its spec ready to submit if
     the smoke run hasn't finished when you're done.
   - Keep BRAIN-FIX's prediction, or revise it with reasons.
